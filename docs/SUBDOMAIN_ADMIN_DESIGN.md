# 子域名归属与管理隔离

## 已确认的业务规则

- 用户账号全站通用，注册站点和注册域名在建号时写入，之后跨站登录不改变注册归属。
- 每张订单在创建事务内保存站点 ID 和请求域名，拆分订单继承；支付回调和管理员调整不重新判断来源。
- 管理员与站点为多对多关系，每次授权独立配置统计、注册用户、订单和访问记录菜单。
- 菜单权限属于具体管理员个人；同一子站可分别为 A 配置订单客服、B 配置用户查询、C 配置统计。后台的菜单组合仅复制个人勾选项，没有共享“子站管理员角色”导致的联动。
- 被设置为子站管理员的账号持续受限，即使所有授权被撤销也不会恢复全局权限。只有超级管理员维护站点和授权。
- 子站管理员使用独立工作台和专用查询 API；所有旧的全局业务 API 默认拒绝，避免通过钱包、退款、报表、导出等关联入口泄露其他站点信息。
- 订单买家可能注册于另一站；订单视图仅返回履约所需的邮箱、商品和订单信息，不包含全站用户档案、其他订单或钱包余额。

## 站点与访问

- 只有总管理员登记的精确域名有效，不根据客户端 query/body/Referer 推断订单来源。规范化大小写、尾点、端口。
- 自营子站与已有 reseller 分销站分开：子站不创建分销用户或自动改变售价、分润。
- 子站只用于来源归属和管理，支付复用主站已配置的通道、商户、手续费、验签及回调。自营子站不覆盖网关同步回跳地址，也不要求向支付服务商登记每个子域名；现有通道的 `notify_url`、`return_url` / `success_url` 继续使用主站 `gptpaynow.com` 配置。
- 子站订单进入 `/pay` 时跳转到主站 `payment_origin`。主站通过 Redis 中短期、订单限定的支付上下文读取该订单；上下文不包含长期 JWT，游客密码不出现在 URL，也不能读取其他订单、钱包或用户中心。
- 主站 `/pay` 返回的页面不会再次创建或替换上下文，因此不会在子站与主站之间循环跳转。上下文默认 10 分钟有效，Redis 不可用时子站不会生成跳转链接，避免伪造或不可恢复的支付会话。
- 主站 `gptpaynow.com`、`www.gptpaynow.com`、`pay.gptpaynow.com` 的来源解析不查询子站目录，避免主站请求新增此依赖。
- 站点域名创建后不可重分配，不物理删除，停用后禁止新注册/下单和前台访问；历史记录仍可统计。
- 来源判断使用请求 Host；不接受客户端提供的转发 Host；反向代理必须原样保留 Host。同源部署 API 是准确归属的前提。
- 公开访问入口按匿名浏览器标识和站点、日期去重；认证请求可以关联用户 ID。标识只存散列，不采集密码、IP 或请求体。
- 无来源历史订单/账号保持未知，不以当前访问或注册站点倒推订单归属。总管理员可在工作台选择全部或未知来源。

## 统计定义

- 日期为 Asia/Shanghai 的左闭右开自然日范围，数量仅计主订单，金额按币种分组，禁止混加。
- 订单数/注册数按创建时间；财务统计为所选创建期订单截至查询时的累计状态（订单同期口径，不是现金收付日口径）。
- 收入取已支付主订单总额扣累计退款；成本取订单项创建时成本快照，父子订单项只计算一次；扣商家承担的成功支付手续费减已退手续费。
- 默认不因退款自动冲回采购成本（卡密退款不等于供应商返还成本）。税费从销售收入剔除；利润为上述范围内估算毛利，不含人工、税负、营销和实际成本追补。
- 展示成本为零的订单数，提示成本缺失时利润可能高估。

## 后台入口与配置

1. 总管理员登录现有后台，进入「子站管理 → 子站工作台 → 站点与管理员」。
2. 创建 `abc.gptpaynow.com` 等一级子域名站点；根域名取 `reseller.subdomain_base`，未配置时使用 `gptpaynow.com`。
3. 在现有「权限管理」创建普通管理员。回到子站工作台的「管理员个人菜单授权」，选择具体账号，再按站点勾选经营统计、注册用户、来源订单、访问记录，或使用运营查看、订单客服、财务查看、用户查看组合快速填写。每站可配置多名管理员，每位管理员可配置多个站点及不同菜单；保存只影响当前选中的账号。
4. 子站管理员下次访问会进入工作台；其权限与数据范围由后端逐次请求校验，原有全局角色不能扩大范围。此次子站工作台提供查询能力，退款、改用户状态、导出、全局设置等操作仍由总管理员执行。
5. 后台内部路由为 `/site-console`，部署后加现有 `web.admin_path` 前缀；不新开独立管理员密码体系。站点管理员可从任意后台入口登录，授权范围不随登录域名变化。

## 运维前提（本次未执行）

- DNS 为每个子域名或通配符记录指向同一应用，TLS 证书覆盖实际子域名。仅匹配主域名的旧证书不能覆盖 `abc.gptpaynow.com`。
- 浏览、注册、下单时子域名不能重定向到 `www`，以便准确记录来源；反向代理使用 `proxy_set_header Host $host`，这些 API 使用当前同源 `/api/v1`。支付网关通知和完成回跳继续使用主站配置；不要为子站复制支付通道或更换主站商户配置。
- 新表及来源字段纳入现有启动迁移；旧用户/订单来源 ID 默认为 0，不修改历史归属。为以后追溯保留实际域名字符串。
- Google/OAuth 提供方需另行登记实际允许的登录子域名和回调地址。自营子站支付同步回跳不返回子站，沿用主站通道配置。此版本 `/pay` 收银台页面仍使用现有同源入口，不新增全站 Cookie、跨域令牌或游客密码传递；将收银台页面也集中到主站需另行确认与实现。
- 自营子站域名与旧分销域名互斥；关闭旧分销功能不影响自营子站。
