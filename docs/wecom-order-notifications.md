# 企业微信新订单通知

后台路径：系统设置 → 通知中心 → 企业微信 · 新订单推送。

- 在企业微信群添加群机器人，保存其 HTTPS Webhook，然后开启通知。
- 已保存的地址不回显；输入框留空保留原配置。可替换地址，或清除并关闭。
- “发送测试消息”只向已保存的群发送明确标注的测试消息，不创建订单、不扣款。
- 新商品订单创建成功、事务提交且超时取消任务入队后，发送一条主订单通知。拆分子单不会分别重复通知。
- **包含待支付订单，不代表已收款。** 是否付款、是否需要交付，必须以订单管理页面当前状态为准。本功能不发送支付成功、余额充值或补开发票事件，也不改变其他渠道的场景开关。
- 后端异步发送，关闭浏览器仍可通知。不影响订单支付、采购或交付。
- 消息仅包含订单编号、商品名称与数量、金额币种、下单时间（UTC+8）以及创建状态，不包含邮箱、卡密、账号密码、Session、Token、人工交付表单。
- 仅接受腾讯官方 `qyapi.weixin.qq.com` 群机器人 HTTPS 地址，不跟随 HTTP 重定向。Webhook 不下发公开配置，专用与通用后台读取接口均脱敏。
- 通知中心日志可按“企业微信 / 新订单创建”筛选成功、失败与测试记录。日志中接收人为 `configured-group`，不是含密钥地址。

## 可靠性与限制

现有 Redis / Asynq 任务队列必须正常运行。发送失败最多重试 15 次；按机器人限制发送速率（间隔至少 3.1 秒）。仅在企业微信返回成功后记录 30 天去重标记，网络故障不会提前消耗去重标记。机器人删除、Webhook 失效或重试耗尽时，需要在日志中排查、重新配置。

通知不承担订单财务状态判定。在极端网络中断（平台已接收但响应丢失）、Redis 回执写入失败或进程崩溃情况下，外部 Webhook 无法保证严格 exactly-once，仍可能出现重发。订单提交与通知任务入队也不是同一个数据库事务；Redis 故障时入队失败会记录 `order_created_notification_enqueue_failed`，不会让客户已经提交的订单报错。管理后台订单记录始终是权威数据。

## 验证

- Go 测试覆盖 Webhook 白名单、配置保存/清除/保留/脱敏、发送失败重试、成功去重、UTF-8 长度、重定向与错误信息脱敏、群通知开关、主单创建与失败订单不发通知。
- `python scripts/verify_wecom.py` 使用全模拟 API 检查中文、繁体、英文以及桌面/移动配置流程，不访问机器人。
- 发布脚本 `scripts/deploy_wecom.py` 只上传列出的文件并重建 app 服务，备份数据库和回滚镜像。其 `configure` 子命令从标准输入读取 Webhook，不写入源码；会发送一条明确标注的真实测试消息。

接口依据：[企业微信消息推送配置说明](https://developer.work.weixin.qq.com/document/path/91770)。
